# Tasks

- [ ] **Metering (anti-clipping) — implementováno, živé ověření nedokončeno kvůli pádu FSP (2026-08-08).** `MidiBridge.enable_channel_meter(channel, level=, peak_hold=, signal_present=)` posílá SysEx handshake (`F0 00 00 66 14 20 ii mm F7`), `_on_midi_in`/`_handle_meter_message` parsují příchozí `D0, XX` (Channel Pressure — kanál 3 bity v horním nibblu datového bajtu, úroveň 0-C=0-100%/E=set overload/F=clear overload ve spodním nibblu). Jednotkově otestováno (`TestChannelMetering`, 193/193 testů zelených). **Živý test (`diag_meter.py` ve scratchpad, throwaway):** povoleno metering na kanálu 0, 20s poslechu — nepřišla žádná `D0` zpráva, jen self-echo vlastního SysEx z loopMIDI. Nejasné proč: (a) hrálo vůbec něco na kanálu 0 během testu?, (b) SysEx model ID `0x14` (Mackie Control Universal) možná není to, co Studio Pro pro tuhle konkrétní zprávu očekává — spec je pro Logic Control hardware (`0x10`), ne obecné MCU; nemáme potvrzeno, který Studio Pro skutečně vyžaduje, (c) FSP spadlo hned po testu (podobná nestabilita jako u dB kalibrace) — nejisté, jestli test proběhl čistě předtím, nebo jestli nestabilita ovlivnila výsledek. Žádný z těchto bodů zatím vyloučen. Až se bude pokračovat: zkusit i model ID `0x10` pro srovnání, ujistit se že na testovaném kanálu skutečně hraje signál, a mít klidný/čerstvě restartovaný stroj.
- [ ] **LCD text (SysEx) — možné řešení "jak zjistit číslo kanálu HELPERS" bez ručního zadávání.** `<Hdr>, 12, oo, yy…, F7` nese text pro scribble-strip (jméno kanálu). Blocker: `python-rtmidi`'s `MidiIn` defaultně ignoruje SysEx (`ignore_types`), `MidiBridge` to nikdy nezměnila — i kdyby Studio Pro posílala jména kanálů, `_on_midi_in()` by je teď neviděla. Potřeba `self._in.ignore_types(sysex=False, ...)` + SysEx parser.
- [ ] **V-Pot (`set_pan`) encoding — podezření na chybu, nedoauditováno.** Spec: `B0, 1i, XX`, XX = relativní delta (bit směru + 0-63 tiků). Naše `set_pan()` formule vypadá jinak, než by měla podle tohohle — potřeba pořádně projít a případně opravit + otestovat.
- [ ] **Dokončit dB kalibraci faderu pod -20dB (do -48dB), přepnout na přímé nastavování + čtení displeje.** Máme spolehlivá data 0 až -20dB (viz Done). Postup příště: posílat `set_fader` s konkrétní hodnotou (0-100), uživatelka přečte dB z displeje — nezávisí to na nespolehlivém `MidiIn` feedbacku (ten po pádu FSP přestal fungovat pro ruční pohyby, i když `MidiOut` fungoval dál).
