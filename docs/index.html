How it works

No API? No problem.

Studio One has no public remote API, so StudioOneMcp drives it through four push-based paths — with a MIDI→command control surface as the reliable backbone.

224built-in commands, dispatchable by name — verified end-to-end
4control paths (MIDI→command · MCU · menu automation · macros)
0public API required — it's all push-based

MIDI → command backbone

A control surface maps MIDI CCs to Studio One <Command>s. The MCP sends a CC → the command fires. Reliable, no Accessibility.

MCU MIDI

Faders, pan, mute, solo, transport via the built-in Mackie Control Universal surface.

Menu / keyboard automation

Clicks menus & sends shortcuts via System Events; verifies actions via the Edit▸Undo label.

Macro generation

Writes .studioonemacro files for command sequences with no shortcut.

Scope: the 224 mapped commands are Studio One built-ins. User macros don't dispatch from a control surface (they need a keyboard/Command-Bar trigger) — tracked on the roadmap.
Setup

Four steps

Install

pip install -e ".[dev]" in the repo (Python 3.10+).

Install the control surface

Copy studio-one-devices/StudioOneMCPPads/ into Studio One's User Devices, add it in External Devices, set Receive From = StudioOneMCP (no Send To).

Run the server

studio-one-mcp --port-name StudioOneMCP — it opens the virtual port Studio One binds to.

Connect your MCP client

Point Claude Desktop (or any MCP client) at the server and start driving your DAW by name.

Vision
